# calc · 실물 계산기 기반 UI/UX 및 기능 설계

작성일: 2026-10-26  
운영: https://softm.github.io/calc/  
저장소: https://github.com/softm/calc

## 디자인 의도

실물 계산기의 빠른 조작과 분명한 구분(숫자 / 기능 / 연산자 / 결과)을 유지하면서
웹의 계산 기록·검색·저장·계산노트 장점을 결합한다. 계산기 화면을 먼저 보이고,
기록과 부가 기능은 필요할 때만 펼친다.

## 참고 사진의 사용성 요소

| 참고 유형 | 가져온 특징 | 앱 구현 |
| --- | --- | --- |
| 8자리 슬림 | 작은 면적의 4열 배치 | 기본 숫자판 |
| 12자리 사무용 | M+, M−, MRC/MC·MR, GT, MU, 00, 큰 연산자 | 사무 모드 |
| 탁상용 대형 | 크고 눌림이 명확한 버튼 | 44px 이상 기능 버튼, 모바일 터치 면적 |
| 공학용 | 수식과 결과, 함수 키패드 | 공학 모드(기존 엔진) |
| 크림·핑크 계산기 | 부드러운 케이스 색감 | 크림·핑크 테마 |

## 주요 상태 / 사용 흐름

1. 처음 진입하면 기본 모드가 나타나며, 마지막 모드·테마·입력식을 복원한다.
2. 사무 모드에서 MC/MR/M+/M−와 GT 합계 상태를 숫자판 바로 위에서 확인한다.
3. 사무 모드 `200 + 10%` → 220, `200 − 10%` → 180; 기본·공학은 수학식 규칙 유지.
4. `100 ÷ 20` 입력 후 MU → 목표 매출이익률 20% 적용 판매가 125. 이 버튼은 원가 단순 가산율이 아닌 매출이익률 계산임을 UI 도움말에 명시한다.
5. `=` 입력 시 계산 기록에 모드·수식·결과를 함께 보관한다. 사무 모드에서만 GT 누적.
6. 모바일에서는 최근 기록을 접어 기본 계산 공간을 확보한다.
7. 계산 기록과 노트는 기존 로컬 저장소를 계속 사용하며 서버로 전송하지 않는다.

## 구현 및 검증 경로

- `index.html`: 테마 선택기, 사무 키, 메모리 상태, 모바일 기록 토글
- `app.js`: 사무 상태·메모리·GT·MU와 기록 모드 복원
- `office.js`: 사무 퍼센트 및 매출이익률 계산(일반 계산 엔진 유지)
- `hardware.css`: 반응형/테마/물리 키패드 시각 효과
- `sw.js`: 신규 파일과 캐시 버전
- `test/office.test.js`: 퍼센트, MU, 메모리 정밀도 회귀 테스트
- `.github/workflows/ci.yml`: `npm test` 및 `npm run check`

## 추가 브라우저 검증 권장

- 모바일 360px/390px 및 PC 1280px에서 영역 겹침·스크롤·광고 간섭 확인
- 키보드·터치·색상 대비·다크 테마·스크린 리더 라벨 확인
- 오프라인 재접속 및 구형 서비스 워커 업데이트 배너 확인
- 기존 저장 기록/계산노트가 유지되고, 사무 모드에서 만든 수식을 불러왔을 때 모드가 복원되는지 확인

## 작업 화면 밀도 원칙 (2026-10-26)

모바일과 데스크톱 모두 **첫 화면에 계산 입력창·숫자판이 바로 보이는 것**을 최우선으로 한다.
앱 내부의 계산기와 계산노트는 이미 작업 공간이므로, 마케팅용 소개 문구를 반복하지 않는다.

| 기존 요소 | 결정 | 이유 |
| --- | --- | --- |
| `YOUR EVERYDAY COMPANION`, `계산은 가볍게.`, 설명 문장 | 삭제 | 계산기 탭 자체로 목적이 전달됨 |
| `A LITTLE MORE ORGANIZED`, `숫자에 맥락을.`, 설명 문장 | 삭제 | 계산노트 탭과 필드가 기능을 설명함 |
| `내 기기에 저장` 소개 배지 | 삭제 | 도움말·개인정보 안내로 이동, 작업 중 반복 노출 불필요 |
| 계산창의 `계산식`/`십진 계산` 중복 라벨 | 삭제 | 입력 필드 접근성 라벨은 유지 |
| 미입력/정상 입력 시 안내 문장 | 숨김 | 오류·근삿값·저장 상태만 표시 |
| 계산기 아래 키보드 설명·노트 이동 CTA | 삭제 | 단축키 도움말 및 상단 탭으로 접근 가능 |
| 계산 기록의 고정 사용법 박스·큰 빈 상태 일러스트 | 삭제 | 빈 상태는 한 줄만 표시 |
| 계산노트의 고정 저장 안내·수량/단가 설명 | 삭제 | 도움말과 개인정보 안내에 보존 |
| 하단 중복 브랜드·소개 문장 | 삭제 | 저장·개인정보 버튼만 유지 |

화면 설계 규칙:
- 주요 영역은 상단 탐색바 바로 아래에서 시작한다.
- 입력 전/정상 계산 중에는 반복 안내 메시지를 띄우지 않는다. 오류와 저장 실패는 반드시 표시한다.
- 버튼 터치 목표는 모바일에서 최소 44px 이상으로 유지한다.
- 기존 계산기/계산노트/광고 기능·데이터 모델·브라우저 로컬 저장소는 변경하지 않는다.
- 숫자판/계산 결과/기록 검색은 항상 기능 중심으로 우선 배치한다.
