# calc 광고 운영 계획

## 목적과 원칙

- 계산 흐름을 방해하지 않는 하단 배너만 운영한다.
- 전면 광고, 앱 시작 광고, 보상형 광고는 사용하지 않는다.
- 웹과 Android 앱에서 같은 위치에 광고가 중복되지 않도록 플랫폼별로 하나만 노출한다.
- 계산식, 계산 결과, 기록, 계산 노트는 광고 요청에 포함하지 않는다.
- 광고가 차단되거나 로드에 실패해도 계산기는 그대로 사용할 수 있어야 한다.

## 플랫폼별 구성

| 플랫폼 | 광고 서비스 | 위치 | 식별자 |
| --- | --- | --- | --- |
| 웹 | 카카오 AdFit | 계산기 카드 아래 320×100 배너 | `DAN-HOdtmmqJByjVatTN` |
| Android | Google AdMob | 화면 하단 적응형 배너 | 앱 `ca-app-pub-4219853075548260~2024029030`, 단위 `ca-app-pub-4219853075548260/7140624349` |

웹 배너는 화면에 가까워졌을 때만 광고 스크립트를 불러온다. Android WebView에는 `AdMobNative/1` 사용자 에이전트를 붙이고 웹 AdFit 코드는 이 값을 감지해 실행하지 않는다.

Android 디버그 빌드는 Google 공식 테스트 광고 식별자만 사용한다. 실제 광고 식별자는 릴리스 리소스에만 둔다.

## 동의와 개인정보

- Android 앱 시작 시 Google UMP로 동의 정보를 갱신한다.
- 광고 요청 가능 상태가 된 후에만 Google Mobile Ads SDK를 초기화한다.
- UMP에서 개인정보 옵션을 요구하는 지역에는 앱 하단에 `광고 개인정보 설정` 버튼을 제공한다.
- 광고 처리 항목과 사업자 링크는 `privacy.html`에 공개한다.

## 출시 전 확인

1. 웹 자동 테스트와 정적 사이트 검사를 통과한다.
2. Android 디버그 APK에서는 테스트 광고만 노출되는지 확인한다.
3. 릴리스 AAB의 병합 manifest에 AdMob 앱 ID와 광고 ID 권한이 있는지 확인한다.
4. Google Play의 광고 포함 여부, 광고 ID, 데이터 보안 답변을 실제 구현에 맞게 갱신한다.
5. 공개 웹에서 AdFit 요청이 발생한 뒤 매체 심사 상태를 확인한다.
6. Play 공개 후 AdMob 앱을 스토어 등록정보와 연결한다.
