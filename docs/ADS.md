# calc 광고 운영 계획

기준일: 2026-10-22 (한국시간)

## 1. 배치 계획

계산과 기록의 입력 공간을 우선 확보하면서 웹 운영 비용을 충당한다. [돌봄한눈](https://github.com/softm/homecare-nationwide-care-services-map)의 하단 광고에서 접힘 유지, 한 번만 요청, 광고 외부 조작부와 실패 시 공간 반환 방식을 참고했다.

| 지면 | 적용 | 이유 |
| --- | --- | --- |
| 화면 하단 | 접기·펼치기 가능한 320×100 배너 1개 | 계산기·계산노트에서 같은 지면을 유지하고 사용자가 높이 조절 |
| 키패드·결과 사이 | 미배치 | 입력과 광고를 분리하여 오클릭 및 계산 방해 방지 |
| 기록 목록 사이 | 미배치 | 짧은 기록 목록에 중복 광고를 추가하지 않음 |
| 첫 방문·전면 팝업 | 미배치 | 앱을 열고 바로 계산할 수 있게 유지 |

하단 광고와 본문은 별도 영역이다. `body.adfit-layout`을 세로 flex로 만들고 헤더·계산기·노트·푸터를 `.app-viewport`에서 스크롤한다. 하단 광고를 별도 flex 자식으로 배치하여 현재 화면의 계산 버튼을 덮지 않는다. 광고가 접히거나 사라지면 본문에 그 높이가 돌아온다.

## 2. 실제 광고단위와 운영 설정

| 항목 | 설정·확인 결과 |
| --- | --- |
| 운영 URL | https://softm.github.io/calc/ |
| AdFit 매체 | calc 계산기 · Web · 도구/생산성 |
| 등록 URL | softm.github.io/calc |
| 광고단위명 | 계산기 하단 배너 |
| 광고단위 ID | `DAN-HOdtmmqJByjVatTN` |
| 발급 규격 | 320×100 — PC·모바일에서 같은 크기 |
| 광고단위 상태 | 2026-10-22 관리 화면에서 정상 확인 |
| 매체 상태 | 2026-10-22 관리 화면에서 심사 대기 확인 |
| 소재 새로고침 | 60초 설정을 미설정으로 변경 완료 |
| 대체 광고 | 미설정; 광고 미수신 시 빈 지면 제거 |
| 실 소재 노출 중단 | 미설정 유지 |

기존 계산기 전용 단위를 유지했다. 돌봄한눈 ID를 복사하거나 ID를 임의 생성하지 않는다. 320×50이나 728×90으로 변경하려면 해당 규격으로 발급된 계산기 전용 단위가 먼저 필요하다.

광고단위의 정상 상태와 매체 승인은 별개다. 실제 상용 광고 송출은 매체 심사·광고 재고·브라우저 차단 상태에 따라 달라진다. 매체 심사 대기를 승인으로 기록하지 않는다.

## 3. 접기·펼치기와 실패 처리

| 상황 | 동작 |
| --- | --- |
| 첫 방문 | 표시 가능한 화면에서 기본 펼침 |
| 광고 접기 | 배너를 숨기고 44px 조작부 유지 |
| 광고 펼치기 | 같은 광고 DOM 재사용; 이미 요청했다면 새 요청 없음 |
| 같은 탭 새로고침 | 사용자가 직접 접은 선택 유지 |
| 계산기·노트 전환 | 공통 하단 유지; SDK나 광고 DOM 재생성 없음 |
| 계산식·노트 입력 | 자동 접기; 사용자가 다시 펼칠 때까지 자동 재등장 없음 |
| 대화상자·가상 키보드 | 자동 접기하여 입력 공간 확보 |
| NO-AD·SDK 오류·시간 초과 | 지면 전체와 빈 공간 제거; 자동 재시도 없음 |
| 320px 미만 공간 | 임시 비노출; 폭 복구 시 기존 DOM 재사용 또는 첫 요청 |
| 오프라인·백그라운드 | 새 요청 보류 |
| iframe 내부 미리보기 | 실광고 요청 비활성 |
| AdMobNative WebView | 웹 AdFit 비활성 |

사용자 선택은 `sessionStorage`의 `calc:adfit:collapsed:v1`에 저장한다. 입력 중 임시 접힘과 사용자 선택은 구분한다. 광고 로드 완료·계산 완료·테마 변경이 사용자의 접힘을 해제하지 않는다. 저장소가 제한된 환경에서도 계산기와 광고 조작이 중단되지 않는다.

## 4. 화면·접근성

- 접기 버튼은 실제 320×100 배너 밖의 툴바에 둔다.
- 버튼 최소 높이 44px, `aria-expanded`, `aria-controls`, 키보드 포커스를 제공한다.
- 배너 상하 12px 여백과 경계선을 둔다. 자체 UX 수치이며 공식 승인 보장 수치가 아니다.
- 광고 소재는 원래 크기를 유지하고 축소·가림·클릭 유도 문구·애니메이션을 사용하지 않는다.
- 320px 화면에도 배너 전체 폭을 확보하고 더 좁으면 요청을 보류한다.
- safe area는 별도 하단 여백으로 처리한다.
- 토스트와 모바일 앱 설치 버튼은 실측 `--calc-ad-space` 위에 배치한다.
- 기존 Stitch 색상·테마를 유지한다. 인쇄에서는 광고와 본문 높이 제한을 제외한다.

## 5. SDK와 오프라인 캐시

`adfit-config.js`는 공개 단위 설정, `adfit.js`는 상태와 요청, `adfit.css`는 화면 배치를 담당한다.

1. 설정·ID·규격·문서 가시성·네트워크·화면 폭과 네이티브/iframe 여부 확인.
2. 펼쳐진 지면에서만 최초 ins와 공식 SDK 생성. 런타임 및 스크립트 중복 방지.
3. 공식 `data-ad-onfail` 콜백으로 광고 미수신 처리.
4. iframe DOM을 관찰하여 성공 콜백만 기다리는 구조를 피함.
5. SDK 다운로드와 광고 응답에 각각 최대 30초 대기. 백그라운드·오프라인 대기는 보류.
6. 실패 후 늦게 온 콜백이 지면을 다시 열지 못하게 처리.
7. 접기·계산·화면 전환에 따른 SDK 반복 삽입 또는 광고 재요청 없음.

관리자 소재 새로고침도 미설정으로 맞췄다. 외부 SDK와 광고 응답은 서비스워커 캐시에 저장하지 않으며 앱 정적 파일만 버전 단위로 갱신한다.

## 6. Android와 개인정보

기존 Android 네이티브 AdMob 구성은 유지한다. `AdMobNative/1` 사용자 에이전트가 있으면 웹 AdFit을 호출하지 않는다.

| 플랫폼 | 광고 서비스 | 식별자 |
| --- | --- | --- |
| 웹 | Kakao AdFit | `DAN-HOdtmmqJByjVatTN` |
| Android | Google AdMob | 앱 `ca-app-pub-4219853075548260~2024029030`, 단위 `ca-app-pub-4219853075548260/7140624349` |

계산식·결과·기록·계산노트는 광고 요청에 넣지 않는다. 광고 접기 선택은 현재 탭에만 보관한다. 광고 사업자의 처리 항목과 링크는 [개인정보처리방침](../privacy.html)에 공개한다. Android의 UMP 동의 및 디버그 테스트 광고 원칙도 유지한다.

## 7. 검증·운영

| 범위 | 확인 내용 |
| --- | --- |
| `npm test` | 계산 엔진·입력·광고 생명주기 회귀 검증 |
| `npm run check` | JavaScript 구문, 상대 경로, 필수 리소스, PWA 캐시 |
| 브라우저 | PC·모바일 접기/펼치기, 입력 자동 접기, 노트 전환, 스크롤·가림 |
| 실패 조건 | NO-AD, SDK 오류, 시간 초과, 저장소 제한, 숨김 탭, 폭 복구 |
| 플랫폼 | 네이티브 WebView와 iframe에서 불필요한 호출 없음 |
| 배포 | main 커밋의 Pages 빌드 성공 및 운영 화면 반영 |

운영 후 매체 승인 상태, 요청 대비 노출, 모바일 사용 불편과 빈 지면 발생을 확인한다. 초기 지면은 하단 1개로 유지하고 확장은 사용성을 검토한 뒤 판단한다. 광고 클릭을 통한 동작 테스트는 하지 않는다.
